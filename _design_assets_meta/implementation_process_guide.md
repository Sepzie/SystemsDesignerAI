# AI System Designer: Project Implementation Process Guide

## Previous Implementation: Project Creation Workflow

We've successfully collaborated on implementing the project creation workflow for the AI System Designer application. Our approach included:

1. **Creating a series of explicit coding prompts for the developer to implement:**
   - **Prompt 1:** Analyzing the codebase and creating the project form UI
   - **Prompt 2:** Implementing the project API route
   - **Prompt 3:** Connecting the form to the API and implementing database operations
   - **Prompt 4:** Setting up project listing and navigation
   - **Prompt 5:** Creating minimal E2E tests for the workflow

2. **Key design decisions:**
   - Building each component one step at a time
   - Focusing on essential functionality first
   - Using data-testid attributes for more maintainable testing
   - Documenting future test possibilities through code comments

3. **Deliverables created:**
   - Project creation form component
   - API routes for project creation
   - Database integration
   - Basic validation and error handling
   - Minimal E2E testing suite

## Process for Next Implementation Phase

To implement the next feature of the AI System Designer, we'll follow the same effective pattern:

1. **Initial Assessment:**
   - Identify the specific feature to implement next
   - Review related documentation and diagrams
   - Understand where it fits in the overall application architecture

2. **Feature Breakdown:**
   - Analyze the feature to determine its core components
   - Identify dependencies and touchpoints with existing code
   - Break down the implementation into manageable pieces

3. **Creating Explicit Coding Prompts:**
   - Develop 4-5 distinct, targeted coding prompts for developers to implement
   - Each prompt should focus on a specific aspect of the feature (UI, API, database, etc.)
   - Include clear instructions, acceptance criteria, and deliverables
   - Make each prompt specific enough to guide implementation but flexible enough for creative solutions
   - Design prompts to be executable in sequence, with each building on the previous work

4. **Creating a Dedicated Testing Prompt:**
   - Develop a separate, focused prompt specifically for testing the implemented feature
   - Include instructions to examine the actual implementation first before writing tests
   - Specify what should be tested and what can be omitted
   - Provide guidance on documenting future test possibilities through code comments

5. **Documentation Through Prompts:**
   - Ensure each prompt serves as documentation for that aspect of the feature
   - Use the prompts themselves as a record of design decisions and implementation approaches
   - Have coding agents document key decisions within the code
